# System threat model

Scope: the code in this repository (server, worker, CLI, Go SDKs, examples) as
deployed per [docs/operations/installation.md](../operations/installation.md).
Method: assets, trust boundaries (docs/plan.md §4, §25.2) and STRIDE per component.
Each mitigation names the code that implements it and the test that exercises it;
"residual" lists what is not mitigated. Test IDs refer to docs/plan.md §33.2 and
appear in test names or comments under `tests/` and `internal/`.

This document reflects code review, not an independent security assessment
(SEC-018 has not been done).

## Assets

| Asset | Where | Why it matters |
| --- | --- | --- |
| Root, pepper and signing-wrap keys | Operator-provided files, environment, secret stores or KMS-wrapped files; unwrapped in process memory | Decrypt every stored secret; wrap signing keys |
| Signing private keys | `signing_keys` (encrypted) | Forge any access/ID token for offline verifiers |
| Password verifiers, TOTP seeds, recovery-code verifiers, passkey public keys | `credentials`, `recovery_codes`, `webauthn_credentials` | Account takeover |
| Bearer artifacts: refresh tokens, codes, session cookies, opaque/support tokens, API keys, PATs, client secrets, invitation/setup/reset/OTP codes, handoff codes, download tokens | Digests or HMAC verifiers in the database; plaintext only in transit and in the encrypted notification payloads | Impersonate a user, client or service |
| Session, grant, membership and role state | `sessions`, `authorization_grants`, `memberships`, `role_assignments` | Decides who may get tokens and what they may do |
| Tenant boundaries | `realm_id` / `organization_id` everywhere | Cross-tenant disclosure |
| Personal data | [data-inventory.md](../operations/data-inventory.md) | Privacy |
| Audit evidence | `audit_events`, `audit_batches`; imported history in `imported_audit_events` (not evidence of this server) | Accountability, incident response |
| Configuration (clients, redirects, policies, webhooks) | Database, config file | Redirect hijack, privilege changes, exfiltration endpoints |
| Lifecycle workflow definitions and plugin packages; trusted plugin publisher keys | `workflows`, `workflow_revisions`, `plugins`, `plugin_versions`; `extensions.plugin_publishers` in the config file | Automated role grants, removals and suspensions in the publisher's name; configuration installed as a reviewed unit; a publisher key decides which packages can be installed |
| Migration exports and converted import documents | Operator machines (`identity-cli migrate-from` input, `--write-documents` output), `POST /migration-plans` request bodies (memory only) | Password verifiers, TOTP seeds and client secrets of the source system |

## Actors and trust boundaries

| Boundary | Inside | Outside | Enforcement |
| --- | --- | --- | --- |
| Internet → public listener | Server | Browsers, clients, attackers | TLS (proxy or `server.tls_*`), body/header/time limits, load shedding, rate budgets |
| Public metadata | — | Anyone | Discovery, JWKS: read-only, no secrets |
| Public protocol initiation | — | Anyone | Client and redirect validation before any state (`oauth.validateInteractive`) |
| Transaction-bound | Transaction holder | Others | Continuation secret (header) or cookie + CSRF + Origin (`authentication.lockTx`) |
| User self-service | User | Other users, machines | Account-audience JWT + live session check; `a.self` rejects machine tokens |
| Tenant administration | Organization administrators | Other organizations | `org.*` permissions in the organization scope (`orgGuard`); 404 for organizations without any permission |
| Provisioning (SCIM) | Provisioning connectors | Other organizations, accounts the connector did not provision | Per-connector bearer token (`pa_scim_`, digest only), bound to one organization, resource types and a role ceiling (`provisioning.Authenticate`); trust class `provisioning` |
| SAML counterparties | Registered SAML applications (SPs) and SAML connections (IdPs) | Other XML senders and receivers | Pinned certificates and entity IDs, exactly registered ACS URLs, single-use correlation bound to the browser, a parser that refuses DTDs and comments, `goxmldsig` verification; metadata uploaded, never fetched ([saml.md](saml.md)) |
| Directories → accounts | LDAP/AD and outbound SCIM connectors of a realm or one organization | Other organizations, protected and privileged accounts, accounts another source owns | Encrypted write-only credentials, verified TLS, egress checks at connection time, failover only on transport errors, ceilings bounded by the creator's, deletion threshold ([directory.md](directory.md)) |
| Realm administration | Realm administrators | Organization admins, users | Admin-audience JWT from an MFA session (`a.admin`, `requireMFASession`), `realm.*` permissions |
| Plugin publisher → realm | Packages signed by an operator-trusted key, reviewed and installed by realm administrators | Unsigned or unknown packages, other publishers | Ed25519 signature over the manifest with the payload digest, `extensions.plugin_publishers`, name ownership, review and declared-permission ceilings ([plugins.md](../integrations/plugins.md)) |
| Workflow runs → realm state | The accountable publisher's authority, re-checked per effect | Workflow subjects, triggering events | Bounded step vocabulary, delegation ceiling at publication and run time ([workflows.md](../integrations/workflows.md)) |
| Support | Support operators | Everyone else | Dedicated permissions, recent MFA, opaque tokens, resource opt-in ([impersonation.md](impersonation.md)) |
| Resource servers | Registered introspectors | Other clients | Client authentication + per-audience introspection registration |
| Operator channel | `identity-cli` operator commands | API users | Local access to the database and keys; no network endpoint |
| Internal listener (and the optional worker listener `workers.metrics_listen`) | Monitoring | Everyone else | Network placement; optional bearer (`server.metrics_token`) for `/metrics` and `/status` |
| Server → outbound | Worker, federation, pre-action hooks, challenge providers, LDAP directories (`directory.egress_allowlist`), outbound SCIM | Internet and private networks | Egress policy: address checks at connect time, no redirects, size/time limits; optional residency allowlist (`privacy.residency`) |
| Server → telemetry | OTLP exporter (`observability.otlp_endpoint`) | Collector | Operator-configured endpoint; span metadata only |
| `Host` → realm | Public origin and verified custom domains | Other host names | `server.host_policy: strict`; issuer never derived from `Host` |
| Application role → database | Server, worker, CLI | Database superuser, schema owner | Append-only triggers; optional runtime role with data privileges only and audit pruning only through `proudauth_audit_prune` (`storage.runtime_role`, OPS-013, AUD-007); application cannot prevent a superuser or owner from editing data |
| Security-event exchange (AUD-016, ADV-007) | Receiver machine clients with `realm.ssf_streams.manage`; registered transmitters | Other clients, unregistered senders | Admin-audience client-credentials tokens and per-client streams; per-transmitter push secret, signature, issuer, audience, age and replay checks, explicit action policy ([cross-system-trust.md](cross-system-trust.md)) |
| Registry clients → registry token endpoint (ADV-010) | Holders of credentials minted for the registry's resource; anonymous callers for anonymous-pull rules | Everyone else | HTTP Basic credential check, per-action permission and scope checks, short-lived tokens for the registry audience ([cross-system-trust.md](cross-system-trust.md)) |
| RP pages → check-session iframe (OIDC-014) | Origins registered for the client | Other origins | Origin check before answering; state recomputed with the sender's origin ([cross-system-trust.md](cross-system-trust.md)) |

The application-provided login UI is **outside** the trust boundary for
decisions: it can only submit proofs; the server decides completion (AUT-004).
